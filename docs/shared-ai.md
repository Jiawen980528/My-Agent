# 全站统一 AI 配置

统一入口位于量化面板「设置 → AI 设置」。MyAgent 主站、量化工具助手和分析功能共用该配置。

## 配置与选择

1. 填写接口地址和对应平台的 API Key。模型输入框右侧可请求平台真实的模型列表；平台不提供列表时仍可手工填写模型 ID。
2. 测试并保存。保存新的接口或模型时会保留之前已保存的配置，密钥仅保存在服务器 `secrets.json` 中，列表不返回密钥。
3. 「全站 AI 模型」可以选指定配置，也可以选「自动选择」。自动模式优先使用当前配置，请求失败且尚未产生输出时尝试其他已保存的配置。先手动选一个模型，再切回自动，可将其设为优先配置。

自动选择只使用实际保存并配置密钥的接口，不会自动购买、开通或猜测模型。图片原样传入模型，不会被丢弃后退化为纯文本回答；是否支持图片取决于该模型的真实能力。流式回复开始后不切换模型，工具执行完成后也不从头重放任务。

主站聊天可以针对单条任务指定已保存的模型，或跟随自动策略。共享模式下主站的旧模型设置入口指向统一配置页。未启用共享模式的独立 MyAgent 安装保持原有配置行为。

## 服务间调用

MyAgent 使用内部 OpenAI 兼容网关 `/api/bridge/ai/v1`。网关校验服务器内部令牌，按已保存配置选择模型并补充上游 API Key，浏览器和 MyAgent 不需要持有上游模型密钥。

`SHARED_AI_ENABLED=1` 启用主站共享配置。`TICKFLOW_BRIDGE_URL` 指向量化服务，`TICKFLOW_BRIDGE_TOKEN` 必须与量化服务匹配。浏览器请求统一使用应用挂载前缀 `/quant`；聊天、状态、动作确认、会话同步和偏好同步都不能绕过该前缀。

## 升级与回退

本次部署工具更新同时管理现有的量化和 MyAgent 两个服务。依赖不变时只上传程序和前端静态文件，在服务器复用两个服务各自的运行环境，禁止构建联网下载依赖。

切换前核验两个 Compose 项目、配置文件、数据挂载和依赖，并停止两个服务做一致备份。现有 MyAgent 的模型配置只在服务器内迁入统一配置；不会写入日志或 GitHub。量化端当前配置优先，不会被迁入的重复配置覆盖。

新的内部令牌及 Compose 覆盖文件只写入服务器私有目录，文件权限为 0600。新旧程序镜像及数据备份保留。失败时重启旧程序，数据不自动回写，涉及数据格式变化时必须审查备份再恢复。

健康检查只证明服务启动。部署还会验证 MyAgent 到统一模型列表的连接，并尝试一个不写入聊天历史的最小模型调用；若模型调用失败，日志只打印异常类型，需检查平台额度、模型权限和连接。
